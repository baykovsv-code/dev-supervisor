# T05: Existing-project admission for scenarios A and B

## Objective

Admit existing repositories without inventing architecture or adapting Supervisor to a
single project's document format.

## Scope

- Add a read-only shallow inventory covering languages, entry points, dependencies,
  build/test/deploy surfaces, components, integrations, Git state, documents, risks,
  and unknowns.
- For scenario A, return the external architecture recommendation and finite minimum
  admission checklist.
- For scenario B, return compatible, conditionally compatible, or incompatible with a
  gap/mapping report.
- Revalidate user-corrected documents and generate a Supervisor-compatible plan/index
  only after exact approval.
- Preserve source document and external identifier provenance.

- Files/modules: `supervisor.py`, `prompts/`, `schemas/`, `tests/`.

## Acceptance criteria

- Assessment cannot edit product code or start implementation.
- Findings distinguish evidence from inference and link to reproducible inputs.
- Contradictions and missing authority fail closed with a finite gap list.
- No project-specific parser or state-machine change is generated by admission.
- Approved fixtures for both scenarios yield deterministic compatible indexes.
- The T00 personal-assistant compatibility harness passes unchanged; admission logic is
  never entered for an already controlled T30 project.

## Non-goals

- automatic reconstruction or approval of AS-IS architecture;
- a universal document importer.
